# 安全性の要件（data-contract）

- 出典: `inception/requirements-analysis/requirements.md`（NFR1、NFR8、C2〜C4）、`construction/data-contract/functional-design/rules.md`（BR1.x〜BR4.7）、`inception/contract-design/contract-summary.md`（C1）、`aidlc/spaces/default/memory/project.md`（Mandated・Forbidden）
- U1 は状態を持たない純粋な関数の集まりで、認証・認可・保存・通信を持たない。安全性の要件は「入力の検証」「CSV の安全な符号化」「外部に依存しないこと」「架空データだけを使うこと」に限られる。

## 1. 認証・認可

- 対象外。単一利用者・ローカル完結のアプリで（requirements.md A1）、U1 は利用者を扱わない。

## 2. 要件

| ID | 要件 | 確かめ方 | 出典 |
|----|------|----------|------|
| NFR1.1 | U1 のコードはネットワーク・ファイル・保存領域・時計・乱数に触れない（純粋な関数と定数だけ）。実行時の外部への要求は0件 | 単体テストをネットワークのない環境（Node.js 上の Vitest）で実行して通ること。ESLint の規則で `fetch`・`XMLHttpRequest`・`WebSocket`・`navigator.sendBeacon`・`indexedDB`・`localStorage` の参照を `src/data-contract/` で禁止する | NFR1、C4 |
| NFR8.1 | 書き出す CSV の文字列値（カテゴリ名・メモ）は、表計算ソフトで数式として解釈されない（BR4.5）。読み込みで元の値に戻る（BR4.6） | AC6.2.1〜AC6.2.3 のテストと、`'`・`''`・`'abc`・`'=1`・`''=1`・`=`・`+1`・`-1`・`@x` の往復テスト | NFR8、FR6.3 |
| NFR8.2 | 入力の検証はすべて U1 の規則を通す。検証は例外を投げず、想定外の型（null、数値の代わりの配列など）も項目ごとのエラーとして返す | 想定外の型を与えるテスト | NFR8、FR1.4 |
| NFR8.3 | U1 は値を HTML として組み立てない。エラー文言は固定の文字列で、利用者の入力値を文言に埋め込まない（表示時のエスケープは画面の Unit が行う） | 文言の一覧のテスト（入力値を含まないこと） | NFR8 |
| NFR8.4 | CSV の復号は、閉じていない引用・極端に長い行でも有限の時間で終わり、例外ではなく malformed などの失敗として返す | 閉じていない引用、1行 1MB のテスト | NFR8、FR7.6 |
| NFR8.5 | テスト・サンプル・CSV 例に使うデータはすべて架空とする。実在の個人・口座・取引に由来する値を含めない | テストデータの目視確認（コードレビュー時）。テストデータには「架空」と分かる名前を使う | C2、project.md |

## 3. 脅威と対策

| 脅威 | 対策 | 関連 |
|------|------|------|
| CSV を表計算ソフトで開いたときの数式の実行（CSV インジェクション） | BR4.5 の先頭シングルクォート | NFR8.1 |
| 不正な CSV による処理の停止・暴走 | 復号は線形時間で、引用の不整合は malformed として返す。大きさの上限（1MB・5,000 行）は U6 が先に確かめる | NFR8.4 |
| 想定外の値による例外で画面が止まる | 検証は例外を投げず結果の型で返す（契約 C1、Q2 = A） | NFR8.2 |
| 外部への意図しない送信 | U1 は通信の手段を一切使わない（ESLint で禁止） | NFR1.1 |

## 4. コンプライアンス

- 扱うデータは架空データだけで、個人情報・決済情報を扱わない（C2、C3）。個人情報保護や決済の規制の対象外。
