# ペルソナ

requirements.md の想定 A1（1人の利用者が自分のブラウザで使う単一利用者・ローカル完結のアプリ）に基づき、2人のペルソナを定める（user-stories-questions.md Q1 = B）。名前と人物像はすべて架空である。

## P1 家計を見直す会社員 — 佐倉 ミナ（架空）

| 項目 | 内容 |
|------|------|
| 役割 | 自分の家計を記録し、月ごとに予算と実績を見比べる個人の利用者 |
| 目的 | ・日々の収支を手早く記録する<br>・支出カテゴリごとに予算を決め、使いすぎに気づく<br>・月末に収入・支出・差額を確認する<br>・データを CSV で手元に保存し、必要なら読み込み直す |
| 困りごと | ・記録が面倒だと続かない<br>・入力ミスに後から気づいて直せないと集計が信用できない<br>・保存できたのか分からない状態が不安 |
| 技術への慣れ | 中（表計算ソフトで CSV を開ける程度） |
| 利用頻度 | 記録はほぼ毎日、振り返りは月1〜2回 |
| 利用環境 | 自宅のデスクトップ PC のブラウザ（Chrome / Edge / Firefox / Safari の最新版） |

## P2 キーボードで操作する利用者 — 森 ハルト（架空）

| 項目 | 内容 |
|------|------|
| 役割 | P1 と同じく自分の家計を管理するが、マウスを使わずキーボードだけで操作する利用者 |
| 目的 | ・すべての機能をキーボードだけで使う<br>・今どこにフォーカスがあるかを常に把握する<br>・入力エラーがどの項目かをすぐ知り、そこへ移動する |
| 困りごと | ・ダイアログを閉じた後にフォーカスが迷子になる<br>・色だけで示される状態（超過・マイナス）が分からない<br>・マウスでしか開けない操作がある |
| 技術への慣れ | 高（キーボードショートカットとスクリーンリーダーを日常的に使う） |
| 利用頻度 | P1 と同じ |
| 利用環境 | デスクトップ PC のブラウザ。キーボードのみ。場合によりスクリーンリーダーを併用 |

## ペルソナの関係と優先度

- P1 が主ペルソナ（優先度1）。すべての機能ストーリーは P1 の目的から書く。
- P2 は横断的なペルソナ（優先度1、P1 と同等）。P1 の全機能を P2 も同じように使えることが求められる（FR9、NFR2）。P2 固有のストーリーは群9にまとめ、各機能ストーリーの受け入れ条件にもキーボード操作の観点を含める。
- 2人は別人として描くが、システム上は同じ1人の利用者として扱う（認証や利用者の区別はない）。
