# User Stories 実施判断

## 判断

実施する（Execute）

## 理由

- 利用者が直接操作する画面機能（収支登録、カテゴリ管理、予算設定、月次集計、CSV 書き出し・読み込み）が中心のアプリであり、利用者の行動単位で受け入れ条件を書くことで、テストと Unit 分割の基準になる。
- 入力エラー・空データ・読み込み中・保存失敗・キーボード操作という横断的な観点を、各ストーリーの受け入れ条件として具体化する必要がある。
- 予算の引き継ぎ（FR4.3）や CSV 読み込みのプレビュー（FR7.2〜FR7.4）など、利用者から見た振る舞いを場面ごとに確かめたい業務ルールがある。

## 考慮した要素

| 要素 | 内容 |
|------|------|
| プロジェクト種別 | 新規開発（Greenfield） |
| 利用者向け範囲 | 画面4種＋CSV 入出力。すべて利用者が直接操作する |
| 複雑さの兆候 | 月ごとの予算の引き継ぎ、集計の整合（FR5.4）、CSV の検証とプレビュー、状態表示の区別（FR8） |
| 利用者の種類 | 1人の利用者（単一利用者・ローカル完結、requirements.md A1） |

## ストーリーが最も役立つ領域

- CSV 読み込み（不正行のプレビュー、確定・キャンセル、上限）
- 予算の設定と引き継ぎ、月次集計での予算・実績・残り・超過の表示
- 保存失敗・読み込み失敗・空データの表示の区別
- キーボードだけで完結する操作の流れ
