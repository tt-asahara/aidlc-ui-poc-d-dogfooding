# Bolt 計画

- Bolt（ボルト）とは、作業の一部を1回で設計から実装・テストまで通し、動くもの（テストで確かめられる成果）を仕上げる単位である。
- 出典: `inception/units-generation/`（7 Unit と依存関係）、`inception/contract-design/contract-summary.md`（C1〜C6）、`inception/user-stories/stories.md`、`delivery-planning-questions.md`（Q1〜Q4）、`aidlc/spaces/default/memory/team.md`
- 方針: 1 Bolt ＝ 1 Unit の 7 Bolt（Q2 = A）。危ないところから作る順序（Q1 = A）。Bolt は同時に進めず、1つずつ順に進める（ご依頼：比較の基準として公式の直列実行）。
- ウォーキングスケルトン（最初に端から端まで動く細い一本道を作る方式）は採らない（team.md Walking Skeleton）。どの Bolt にもスケルトンの印は付けない。
- 各 Bolt では、その Unit について Construction の工程（Functional Design、NFR Requirements、NFR Design、Infrastructure Design、Code Generation）を順に行い、各工程で承認を受ける。Code Generation の計画も承認を受けてから作る。
- 作業ブランチは `setup/aidlc-d` から切り、`setup/aidlc-d` に squash マージする（team.md Way of Working）。
- どの Bolt も、マージ前に一括検証コマンド（lint・型チェック・テスト・行カバレッジ 80%）を通す（team.md Testing Posture）。

## B1 — U1 data-contract（共通データ契約）

- **含む Unit**: U1（u1-data-contract）
- **ストーリー**: US1.1、US6.2（関わり：US2.2、US6.1、US7.1、US9.3）
- **完了の条件（Definition of Done）**:
  - C1 の型と関数（検証、CSV の符号化・復号、数式対策の往復、スキーマ版）がすべて実装され、公開窓口 `src/data-contract/index.ts` から公開されている
  - テストを先に書く方針（team.md）に従い、AC1.1.1〜AC1.1.5、AC6.1.3、AC6.2.1〜AC6.2.3 を満たすテストがある
  - CSV の観点（BOM の有無、CRLF/LF、引用符・カンマ・改行を含む値、`'=1` を含む数式対策の往復、閉じていない引用、空ファイル、見出し不一致）のテストがある（Q4：CSV の扱いが心配）
  - 一括検証コマンドが通り、この Unit の行カバレッジが 80% 以上
- **確かめたいこと（confidence hypothesis）**: 画面入力と CSV 読み込みで同じ検証規則・同じ文言が使え、CSV の書き出し → 読み込みの往復で値（メモの記号・改行・数式風の文字列を含む）が一切変わらない。
- **見せ方（demo）**: テストの実行結果。架空のメモ（`=SUM(A1)`、`'=1`、改行入り、カンマ入り）を含む収支の CSV 往復が一致することを示す。

## 実行の設定

| 項目 | 値 | 根拠 |
|------|----|------|
| Construction の進め方 | Unit ごと（unit-major）：1つの Unit の工程をすべて終えてから次の Unit へ進む | 既定値。直列実行のご依頼と一致 |
| 実行方式 | 直列（serial） | ご依頼（公式の直列実行、並列化なし） |
| Unit ごとの完了確認 | 有効（各 Unit の完了時に検証コマンドの結果を確かめ、承認を受ける） | 既定値 |
| 担当 | このセッションで実行（1チーム） | 下記 team-allocation.md |

- 実際に Unit を作る順序は、依存関係（`unit-of-work-dependency.md`）に基づいて決まる。この計画の順序と異なる場合は、risk-and-sequencing-rationale.md の「実行時の順序について」に従う。
