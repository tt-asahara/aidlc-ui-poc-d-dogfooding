# Delivery Planning — 質問

7 Unit（U1 共通データ契約、U2 画面部品、U3 保存、U4 家計簿の中核、U5 月次集計、U6 CSV 入出力、U7 画面）を、どの順でどうまとめて作るかを決めます。作る単位は Bolt（ボルト）と呼びます。Bolt とは、作業の一部を1回で設計から実装・テストまで通し、動くものを仕上げる単位です。

すでに決まっていること（質問しません）:
- 今回は比較の基準として、公式の直列実行で進めます。Bolt は同時に進めず、1つずつ順に進めます（ご依頼より）。
- 最初に端から端まで動く細い一本道（ウォーキングスケルトン）を作る方式は採りません（Practices Discovery で決定）。
- 依存関係の制約から、U7（画面）はほかのすべての Unit の後になります。U3 は U1 の後、U4 は U1・U3 の後、U5・U6 は U4 の後です。

## Q1. 何から作るか

依存関係が許す範囲で、順序の考え方を選びます。

A. 危ないところから：データの正しさに関わる部分（共通データ契約 → 保存 → 中核）を先に作り、次に集計・CSV、最後に画面部品と画面を作る。順序は U1 → U3 → U4 → U5 → U6 → U2 → U7（おすすめ：保存の失敗や別タブ対策など、外から見えにくい誤りを早く見つけられるため）
B. 見えるものを早く：画面部品（U2）を最初に作って見た目を早く確かめ、その後に U1 → U3 → U4 → U5 → U6 → U7
C. 点数づけで決める：各 Unit を価値・急ぎ度・危険度の下げ幅と大きさで点数化し（WSJF：「価値＋急ぎ度＋危険度の下げ幅」を大きさで割った値の高い順に作る方法）、その順に作る
X. Other (please specify)

## Q3. 外部への依存（パッケージの取得）

A. 無償の公開パッケージの取得を許可する（有償のサービス・認証の変更・追加購入はしない）（おすすめ）
B. 取得は許可しない（手元にあるものだけで作る。React・Vite などは使えず、設計の見直しが必要）
